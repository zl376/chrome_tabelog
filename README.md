# Tabelog Score Viewer

Chrome extension that shows [Tabelog](https://tabelog.com) review scores when hovering over restaurant listings on supported sites.

## Supported Sites

- `https://omakase.in/*`
- `https://www.tablecheck.com/*`

## How It Works

1. Browse a supported restaurant listing page
2. Hover over any restaurant block — a tooltip appears with the Tabelog score
3. The tooltip shows: rating score, star visualization, review count, and a link to the Tabelog page

Scores are cached at multiple levels (extension + native host) to avoid repeated requests.

## Installation

### Prerequisites

- [Chrome](https://www.google.com/chrome/) (or any Chromium-based browser)
- [Python 3](https://www.python.org/downloads/) (3.10+)
- [uv](https://docs.astral.sh/uv/) (auto-installed by the script if missing)

### Setup

```bash
git clone https://github.com/<user>/chrome_tabelog.git
cd chrome_tabelog
bash install.sh
```

The install script handles everything:
1. Creates a Python venv with `uv` inside the project folder
2. Installs `curl_cffi` + `beautifulsoup4` (needed to bypass Tabelog's bot protection)
3. Patches `native_host.py`'s shebang to use the venv Python
4. Registers the native messaging host with Chrome

Then in Chrome:
1. Open `chrome://extensions`
2. Toggle **Developer mode** ON (top-right corner)
3. Click **Load unpacked** and select the `chrome_tabelog` folder
4. Done — visit `tablecheck.com/ja/japan` and hover over a restaurant

No server to run, no terminal to keep open. Chrome auto-launches the Python host on demand.

## Architecture

```
tablecheck.com / omakase.in
        │  hover
        ▼
   content.js ──── instant loading tooltip
        │  chrome.runtime.sendMessage
        ▼
   background.js ─── 3-tier cache check
        │  chrome.runtime.sendNativeMessage
        ▼
   native_host.py (auto-launched by Chrome)
        │  curl_cffi (Safari TLS impersonation)
        ▼
   tabelog.com → parsed → fuzzy matched → score returned
```

## Configuration

All site selectors and matching rules are in `config.js`. If a site changes its markup, only this file needs updating:

- **`SITE_CONFIG`** — CSS selectors for finding restaurant blocks + name/location extraction functions
- **`TABELOG_CONFIG`** — Selectors for parsing Tabelog search results
- **`MATCH_THRESHOLD`** — Minimum similarity score for name matching (0.0–1.0)
- **`CACHE_TTL`** — How long scores are cached (in milliseconds)

## Debug Mode

To see which restaurant blocks are detected, run this in the page's DevTools console:

```js
const cfg = SITE_CONFIG[window.location.hostname];
document.querySelectorAll(cfg.restaurantSelector).forEach(el => console.log(cfg.nameExtractor(el), el));
```

Check the service worker console for fetch logs: `chrome://extensions` → click the "service worker" link on the extension card.

## Files

| File | Purpose |
|------|---------|
| `manifest.json` | Extension definition (MV3), stable extension key |
| `config.js` | Site selectors + Tabelog parsing rules |
| `background.js` | Service worker — cache + native messaging bridge |
| `content.js` | Content script — hover detection, tooltip UI |
| `content.css` | Tooltip styling |
| `utils/fuzzy-match.js` | Levenshtein matching with Japanese text normalization |
| `native_host.py` | Python native messaging host (auto-launched by Chrome) |
| `install.sh` | One-command setup script |
| `com.tabelog.proxy.json.example` | Native host manifest template |

## Privacy

This repo contains no personal identifiers. Machine-specific paths are templated and generated by `install.sh` at setup time. The extension key in `manifest.json` is a throwaway RSA key pair used only to pin the extension ID.
